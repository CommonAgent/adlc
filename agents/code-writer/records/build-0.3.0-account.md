Starting from the released 0.2.6 scripts, I changed workspace.mjs and check.mjs and wrote archive.mjs and handoff.mjs; pieces.mjs, report.mjs, verify.mjs and went-without.mjs are the released bytes, and agent-folder.mjs is unchanged and identical to the copy that was attached.

archive.mjs packs a folder as a gzip tar and unpacks one in node alone. Entries are sorted by path, and times, modes and owners are fixed, and the gzip header's operating system byte is fixed, so the same folder gives the same bytes. Paths longer than ustar allows use a pax header. System tar reads what it writes. Reading refuses a path that climbs out, an absolute or drive path, a link, a bad checksum, and writes nothing until every entry has been checked. It is also a command, `node archive.mjs pack|unpack`, which exits 2 with a usage line when arguments are missing.

handoff.mjs lays out the build folder, writes AGENTS.md, CLAUDE.md and build.lock.json, copies check.mjs, workspace.mjs, agent-folder.mjs and archive.mjs into .adlc/, packs the folder, checks that the archive unpacks to exactly what was laid out, and files it as the piece "the build folder" (application/gzip) with pieces.json. A prototype counts as a released package when it carries the agent's files or a file under scripts/; only then are its scripts seeded and its other files put at their own paths. Loose prototype files go under prototype/ and every script is stubbed. A released package's old agent files, skills and tests go under prototype/, never over the new ones. The lock pins every file outside scripts/, records/ and itself. {{name}}, {{version}} and {{scripts}} in the template are filled in when the folder says them.

workspace.mjs now lays a package prototype's files outside scripts/ at their own paths, read-only and pinned; takes a reference the spec names from a loose prototype file with the same name before standing it in as empty (the delivery check does the same, and without it references/agents-md-template.md was an empty stand-in); and, when an attachment is a gzip tar carrying build.lock.json, checks every pinned file against the lock first, refuses naming the file that differs, and otherwise unpacks it as the workspace. check.mjs allows a new test file under test/, says "spec and test steps" when a pinned test or agent file was changed or removed, works where no declaration came, and run from .adlc/ checks the folder it sits in against build.lock.json.

A released package's own references the spec names that nothing carried are stood in as empty and said in the reply. handoff.mjs does not import went-without.mjs, which the hand-off-the-code skill does not carry; what it went without is said in its reply.
